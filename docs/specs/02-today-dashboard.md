# SPEC-02 · 오늘 화면 (Today Dashboard)

| 항목 | 내용 |
|---|---|
| **기능명** | 오늘 화면 — 루틴 체크 · 오늘 할 일 · 오늘 기록 요약 |
| 관련 화면 | `/` |
| 관련 테이블 | `routines`, `todos`, `logs`, `profiles` |
| 우선순위 | P0 (필수) |

---

## 1. 기능 목적

- 앱을 열자마자 **"오늘 무엇을 해야 하고, 지금까지 무엇을 했는지"** 를 한 화면에서 파악하게 한다.
- 루틴 체크와 기록 추가를 **같은 화면에서** 처리해 앱 전환 없이 하루를 마감하게 한다.
- 달성률을 시각화해 지속 동기를 만든다.

---

## 2. 동작 방식

### 2.1 화면 구성 (위 → 아래)

```
┌─────────────────────────────────┐
│ AppBar   8월 3일 월요일   [아바타] │
├─────────────────────────────────┤
│ ProgressCard                     │
│   오늘의 달성률  ▓▓▓▓▓░░░ 62%     │
│   루틴 2/3 · 할 일 3/5 · 기록 4건 │
├─────────────────────────────────┤
│ § 오늘의 루틴                     │
│   ☑ 🧘 아침 스트레칭              │
│   ☐ 💧 물 2L 마시기               │
├─────────────────────────────────┤
│ § 오늘 할 일          [+ 추가]    │
│   ☐ 장보기            (높음)      │
│   ☑ 보고서 제출                   │
├─────────────────────────────────┤
│ § 오늘 기록           [+ 추가]    │
│   🍽 아침 · 오트밀   320kcal [사진]│
│   🏃 하체+러닝 · 55분             │
├─────────────────────────────────┤
│ [오늘] [루틴] [기록] [프로필]      │  ← BottomTabBar
└─────────────────────────────────┘
```

### 2.2 데이터 조회 (서버 컴포넌트에서 병렬 실행)

| 섹션 | 쿼리 |
|---|---|
| 오늘의 루틴 | `routines` where `user_id = auth.uid()` and `is_active = true` and (`repeat_days` 가 빈 배열 **또는** 오늘 요일 포함) |
| 오늘 할 일 | `todos` where `user_id = auth.uid()` and `due_date = 오늘` order by `is_done` asc, `priority` desc, `created_at` asc |
| 오늘 기록 | `logs` where `user_id = auth.uid()` and `logged_on = 오늘` order by `created_at` asc |

> **날짜 기준** — 서버/클라이언트 타임존 차이로 "오늘"이 어긋나는 것을 막기 위해, 오늘 날짜는 **`Asia/Seoul` 기준 `YYYY-MM-DD` 문자열**로 계산해 사용한다.

### 2.3 루틴 체크 동작

루틴 자체에는 완료 상태가 없다. 체크는 **오늘 날짜의 `todos` 레코드 생성/토글**로 구현한다.

| 상태 | 동작 |
|---|---|
| 체크 안 됨 (오늘 파생 todo 없음) | 체크 시 `todos` insert (`routine_id`, `due_date = 오늘`, `is_done = true`, `completed_at = now()`) |
| 체크 안 됨 (오늘 파생 todo 있고 `is_done=false`) | `is_done = true`, `completed_at = now()`로 update |
| 체크됨 | 해제 시 `is_done = false`, `completed_at = null`로 update |

> `todos (user_id, routine_id, due_date)` 부분 유니크 인덱스가 중복 생성을 DB 레벨에서 차단한다.

### 2.4 달성률 계산

```
분모 = 오늘의 루틴 수 + 오늘 할 일 수(루틴 파생 제외)
분자 = 그중 완료된 항목 수
달성률 = 분모가 0이면 0%, 아니면 round(분자 / 분모 × 100)
```

### 2.5 상호작용

| 동작 | 결과 |
|---|---|
| 체크박스 탭 | 낙관적 UI 업데이트 → 서버 반영 → 실패 시 롤백 + 토스트 |
| 할 일 카드 탭 | 수정 바텀시트 열림 (SPEC-03) |
| 기록 카드 탭 | 기록 수정 화면 이동 (SPEC-05) |
| `[+ 추가]` (할 일) | 할 일 생성 바텀시트 |
| `[+ 추가]` (기록) | 기록 생성 화면 |
| 아바타 탭 | `/profile` 이동 |

## 3. 예외 처리

| # | 상황 | 처리 |
|---|---|---|
| E1 | 루틴·할 일·기록이 모두 없음 (신규 사용자) | 온보딩형 빈 상태 — *"첫 루틴을 만들어 하루를 시작해 보세요"* + **루틴 만들기** CTA |
| E2 | 특정 섹션만 비어 있음 | 섹션별 빈 상태 문구 (*"오늘 할 일이 없어요"*, *"오늘 기록이 아직 없어요"*) |
| E3 | 데이터 조회 실패 (네트워크/서버) | 에러 상태 UI + **다시 시도** 버튼. 부분 실패 시 성공한 섹션은 그대로 노출 |
| E4 | 체크 토글이 서버에서 실패 | 낙관적 업데이트 롤백 + 토스트 *"저장에 실패했어요. 다시 시도해 주세요."* |
| E5 | 체크박스 **연타** | 요청 진행 중 해당 항목 입력 비활성화 |
| E6 | 자정을 넘겨 화면에 머무름 | 날짜 헤더 탭 또는 새로고침 시 오늘 날짜 재계산 (자동 갱신은 v1.1) |
| E7 | 루틴이 삭제되었는데 파생 todo가 남음 | `routine_id`가 `on delete set null` → 일반 할 일로 유지 (사용자에게 손실 없음) |
| E8 | 로딩 지연 | 섹션별 스켈레톤 UI 노출 |

## 4. 완료 조건

- [ ] `/` 진입 시 오늘 날짜와 달성률이 표시된다.
- [ ] 오늘 요일에 해당하는 활성 루틴만 "오늘의 루틴"에 나타난다.
- [ ] 루틴 체크/해제가 즉시 반영되고, **새로고침 후에도 유지**된다.
- [ ] 오늘 할 일과 오늘 기록이 각각 조회된다.
- [ ] 각 섹션의 `[+ 추가]`로 할 일·기록을 생성할 수 있고, 생성 즉시 목록에 반영된다.
- [ ] 데이터가 없을 때 빈 상태 UI가 적절히 노출된다.
- [ ] 375px 화면에서 가로 스크롤 없이 모든 요소가 보인다.
