# SPEC-03 · 할 일 (Todo) CRUD

| 항목 | 내용 |
|---|---|
| **기능명** | 할 일 등록 / 조회 / 수정 / 삭제 |
| 관련 화면 | `/` (오늘) — 목록 · 생성/수정 바텀시트 |
| 관련 테이블 | `todos` |
| 우선순위 | P0 (필수) |

---

## 1. 기능 목적

- 사용자가 **오늘 해야 할 일**을 빠르게 등록하고 완료 여부를 관리하게 한다.
- 모든 데이터를 Supabase Postgres에 저장해 **기기·세션과 무관하게 유지**되도록 한다.

---

## 2. 데이터 정의

| 컬럼 | 타입 | 필수 | 제약 / 기본값 |
|---|---|---|---|
| `id` | uuid | ✅ | `gen_random_uuid()` |
| `user_id` | uuid | ✅ | `auth.users.id` 참조, 로그인 사용자로 자동 설정 |
| `routine_id` | uuid | ✖ | 루틴에서 파생된 경우만. 루틴 삭제 시 `null` |
| `title` | text | ✅ | 1~120자 |
| `memo` | text | ✖ | 최대 500자 |
| `due_date` | date | ✅ | 기본 오늘 (Asia/Seoul) |
| `priority` | text | ✅ | `low` / `normal`(기본) / `high` |
| `is_done` | boolean | ✅ | 기본 `false` |
| `completed_at` | timestamptz | ✖ | 완료 시각 |
| `created_at` / `updated_at` | timestamptz | ✅ | 자동 |

---

## 3. 동작 방식

### 3.1 생성 (Create)

1. 오늘 화면 **`+ 추가`** 탭 → 바텀시트 오픈
2. 입력: **제목**(필수) · 메모 · 날짜(기본 오늘) · 우선순위(기본 보통)
3. **저장** 탭 → 서버 액션 `createTodo`
   - 제목 앞뒤 공백 trim, 빈 문자열이면 거부
   - `user_id`는 서버에서 세션으로부터 주입 (클라이언트 입력을 신뢰하지 않음)
4. 성공 → 바텀시트 닫힘 → 목록 갱신 → 토스트 *"할 일을 추가했어요"*

### 3.2 조회 (Read)

- **오늘 화면**: `due_date = 오늘`인 항목
- 정렬: 미완료 우선 → 우선순위 `high > normal > low` → 생성순
- RLS로 `auth.uid() = user_id`인 행만 반환된다.

### 3.3 수정 (Update)

두 가지 경로를 제공한다.

| 경로 | 동작 |
|---|---|
| **① 완료 토글** | 체크박스 탭 → `is_done` 반전, `completed_at` 갱신/제거. 낙관적 UI 반영 |
| **② 상세 수정** | 카드 탭 → 수정 바텀시트(기존 값 프리필) → 제목·메모·날짜·우선순위 변경 → **저장** |

- 서버 액션 `updateTodo(id, patch)` — 변경된 필드만 전송
- `updated_at`은 DB 트리거가 자동 갱신
- 성공 시 목록에 즉시 반영, 토스트 *"수정했어요"*

### 3.4 삭제 (Delete)

1. 수정 바텀시트 하단 **삭제** 또는 카드 스와이프/`⋯` 메뉴
2. 확인 모달 — *"'{제목}'을(를) 삭제할까요? 되돌릴 수 없어요."*
3. **삭제** 확정 → `deleteTodo(id)` → 목록에서 제거 → 토스트 *"삭제했어요"*

## 4. 예외 처리

| # | 상황 | 처리 |
|---|---|---|
| E1 | 제목이 비어 있거나 공백만 입력 | 저장 버튼 비활성화 + 인라인 에러 *"할 일 제목을 입력해 주세요"* |
| E2 | 제목 120자 초과 | 입력 단계에서 최대 길이 제한 + 글자 수 카운터 표시 |
| E3 | 메모 500자 초과 | 초과분 입력 차단 + 카운터 경고색 |
| E4 | 네트워크 오류로 저장 실패 | 바텀시트 유지(입력값 보존) + 토스트 *"저장에 실패했어요. 다시 시도해 주세요."* |
| E5 | 이미 삭제된 항목을 수정/삭제 시도 (다른 탭에서 삭제됨) | 서버가 0행 반환 → *"이미 삭제된 항목이에요"* 안내 후 목록 새로고침 |
| E6 | 세션 만료 상태에서 저장 | `/login`으로 리다이렉트, 재로그인 후 원래 화면 복귀 |
| E7 | 다른 사용자의 `id`로 요청 위조 | RLS가 차단(0행) → *"권한이 없어요"* 안내 |
| E8 | 저장 버튼 **연타** | 요청 중 버튼 `disabled` + 스피너, 중복 생성 방지 |
| E9 | 완료 토글 실패 | 낙관적 업데이트 롤백 + 토스트 |
| E10 | 과거 날짜로 할 일 생성 | 허용 (지난 기록 보완 목적). 단 오늘 화면에는 노출되지 않음을 안내 |

---

## 5. 완료 조건

- [ ] 할 일을 생성하면 목록에 즉시 나타나고, **새로고침 후에도 유지**된다.
- [ ] Supabase 대시보드 `todos` 테이블에서 생성된 행을 확인할 수 있다.
- [ ] 제목·메모·날짜·우선순위를 수정하면 조회 화면에 **반영**되고 새로고침 후에도 유지된다.
- [ ] 완료 체크/해제가 저장되고 새로고침 후에도 유지된다.
- [ ] 삭제한 항목은 목록과 DB 어디에서도 조회되지 않는다.
- [ ] 빈 제목으로는 저장할 수 없다.
- [ ] 다른 사용자의 할 일은 조회·수정·삭제할 수 없다 (RLS).
- [ ] 로컬 스토리지·세션 스토리지를 데이터 저장소로 사용하지 않는다.
