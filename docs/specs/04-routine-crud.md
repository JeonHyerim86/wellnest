# SPEC-04 · 루틴 (Routine) CRUD

| 항목 | 내용 |
|---|---|
| **기능명** | 반복 루틴 등록 / 조회 / 수정 / 삭제 |
| 관련 화면 | `/routines`, `/` (오늘 화면 노출) |
| 관련 테이블 | `routines`, `todos` |
| 우선순위 | P0 (필수) |

---

## 1. 기능 목적

- 매일·매주 반복되는 실천 항목을 **한 번만 등록**하고, 이후에는 체크만 하게 한다.
- "반복 입력 피로(P2)"를 제거해 습관 지속률을 높인다.

---

## 2. 데이터 정의

| 컬럼 | 타입 | 필수 | 제약 / 기본값 |
|---|---|---|---|
| `id` | uuid | ✅ | `gen_random_uuid()` |
| `user_id` | uuid | ✅ | 세션에서 주입 |
| `title` | text | ✅ | 1~60자 |
| `emoji` | text | ✖ | 대표 이모지 1자 |
| `category` | text | ✅ | `health` / `meal` / `mind` / `life`(기본) |
| `repeat_days` | smallint[] | ✅ | 0(일)~6(토). **빈 배열이면 매일** |
| `is_active` | boolean | ✅ | 기본 `true` |
| `sort_order` | integer | ✅ | 기본 0 |
| `created_at` / `updated_at` | timestamptz | ✅ | 자동 |

---

## 3. 동작 방식

### 3.1 생성 (Create)

1. `/routines` → 우측 하단 **FAB `+`** → 생성 바텀시트
2. 입력 항목
   - **제목** (필수, 1~60자)
   - 이모지 (선택 — 프리셋 그리드에서 선택)
   - 카테고리 (건강 / 식단 / 마음 / 생활)
   - **반복 요일** — 일~토 토글. 아무것도 선택하지 않으면 **매일**로 처리
3. **저장** → `createRoutine` → 목록 최상단에 추가 → 토스트 *"루틴을 만들었어요"*

### 3.2 조회 (Read)

| 위치 | 조회 조건 |
|---|---|
| `/routines` | 본인 루틴 전체. 활성 → 비활성 순, 그다음 `sort_order`, `created_at` |
| `/` (오늘) | `is_active = true` **AND** (`repeat_days`가 빈 배열 **OR** 오늘 요일 포함) |

각 카드에 이모지 · 제목 · 카테고리 칩 · 반복 요일 배지(`월 화 수 목 금` 또는 `매일`) · 활성 스위치를 표시한다.

### 3.3 수정 (Update)

| 경로 | 동작 |
|---|---|
| **① 활성 토글** | 카드의 스위치 → `is_active` 반전. 비활성 루틴은 오늘 화면에서 사라짐 |
| **② 상세 수정** | 카드 탭 → 수정 바텀시트(프리필) → 제목·이모지·카테고리·반복 요일 변경 → **저장** |

- 반복 요일을 바꿔도 **이미 생성된 과거 `todos`는 변경하지 않는다** (기록 보존).
- 수정 결과는 `/routines`와 `/` 양쪽에 즉시 반영된다.

### 3.4 삭제 (Delete)

1. 카드 `⋯` → **삭제**
2. 확인 모달 — *"'{제목}' 루틴을 삭제할까요? 이미 만들어진 할 일 기록은 그대로 남아요."*
3. 확정 → `deleteRoutine(id)`
   - `todos.routine_id`는 `on delete set null` → 파생 할 일은 **일반 할 일로 남아 기록이 보존**된다.
4. 목록에서 제거 + 토스트 *"삭제했어요"*

## 4. 예외 처리

| # | 상황 | 처리 |
|---|---|---|
| E1 | 제목 미입력 / 공백만 | 저장 비활성화 + 인라인 에러 *"루틴 이름을 입력해 주세요"* |
| E2 | 제목 60자 초과 | 최대 길이 제한 + 카운터 |
| E3 | 반복 요일 미선택 | 에러 아님 — **"매일"** 로 저장하고 입력 화면에 *"선택하지 않으면 매일 반복돼요"* 안내 |
| E4 | 같은 이름의 루틴 중복 생성 | 허용 (동명이인 루틴 가능). 다만 저장 전 *"같은 이름의 루틴이 이미 있어요"* 경고 표시 |
| E5 | 삭제된 루틴을 오늘 화면에서 체크 시도 | 서버가 0행 반환 → *"삭제된 루틴이에요"* 안내 후 화면 새로고침 |
| E6 | 네트워크 오류로 저장 실패 | 입력값 보존 + 토스트 *"저장에 실패했어요"* + 재시도 |
| E7 | 비활성 루틴을 오늘 화면에서 찾음 | 비활성은 오늘 화면에 노출하지 않으며, `/routines`에서 흐린 스타일로 구분 표시 |
| E8 | 다른 사용자의 루틴 접근 | RLS 차단 → *"권한이 없어요"* |
| E9 | 저장/삭제 버튼 연타 | 요청 중 `disabled` 처리 |
| E10 | 루틴이 하나도 없음 | 빈 상태 UI — *"아직 루틴이 없어요. 작은 것부터 시작해 볼까요?"* + 추천 루틴 칩(물 2L, 스트레칭, 산책) |

---

## 5. 완료 조건

- [ ] 루틴을 생성하면 `/routines` 목록에 즉시 나타나고 새로고침 후에도 유지된다.
- [ ] 반복 요일에 오늘이 포함된 활성 루틴만 오늘 화면에 노출된다.
- [ ] 요일을 선택하지 않고 저장하면 "매일"로 동작한다.
- [ ] 제목·이모지·카테고리·반복 요일 수정이 두 화면 모두에 반영되고 새로고침 후에도 유지된다.
- [ ] 활성 스위치를 끄면 오늘 화면에서 사라지고, 다시 켜면 나타난다.
- [ ] 루틴을 삭제해도 파생된 할 일 기록은 남는다.
- [ ] 삭제한 루틴은 어떤 화면에서도 조회되지 않는다.
- [ ] 모든 변경이 Supabase `routines` 테이블에 반영된다.
