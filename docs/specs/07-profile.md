# SPEC-07 · 프로필

| 항목 | 내용 |
|---|---|
| **기능명** | 프로필 조회 / 수정 · 로그아웃 |
| 관련 화면 | `/profile` |
| 관련 테이블 | `profiles` (+ Storage `avatars`) |
| 우선순위 | P1 |

---

## 1. 기능 목적

- 사용자가 자신의 계정 정보를 확인하고 **닉네임·아바타를 개인화**하게 한다.
- 지금까지의 실천을 **요약 수치로 확인**해 지속 동기를 제공한다.
- 안전하게 **로그아웃**할 수단을 제공한다.

## 3. 동작 방식

### 3.1 조회 (Read)

- `profiles` where `id = auth.uid()` 단건 조회
- 통계는 서버에서 집계 쿼리로 계산한다.

| 지표 | 계산 |
|---|---|
| 루틴 | `routines` where `is_active = true` 개수 |
| 완료 | `todos` where `is_done = true` 개수 |
| 기록 | `logs` 전체 개수 |

- `display_name`이 비어 있으면 이메일 로컬파트를 대신 표시한다.
- `avatar_url`이 없으면 이니셜 원형 플레이스홀더를 표시한다.

### 3.2 닉네임 수정 (Update)

1. 닉네임 행 탭 → 인라인 편집 또는 바텀시트
2. 입력 (1~20자) → **저장** → `profiles.display_name` update
3. 성공 → 화면과 AppBar 아바타 툴팁에 즉시 반영 + 토스트 *"수정했어요"*

### 3.3 아바타 변경

SPEC-06의 업로드 흐름을 그대로 사용한다 (버킷 `avatars`).

1. **사진 변경** 탭 → 파일 선택
2. 검증(형식/5MB) → 업로드 → `profiles.avatar_url` 갱신 → 이전 파일 삭제
3. `/profile`과 모든 화면의 AppBar 아바타에 반영

### 3.4 로그아웃

1. **로그아웃** 탭 → 확인 모달 *"로그아웃할까요?"*
2. 확정 → `supabase.auth.signOut()` → 세션 쿠키 삭제 → `/login` 이동
3. 뒤로가기로 보호 라우트에 재진입할 수 없다 (미들웨어가 차단).

## 4. 예외 처리

| # | 상황 | 처리 |
|---|---|---|
| E1 | `profiles` 행이 없음 (트리거 실패 등) | 세션 정보로 `upsert` 후 재조회. 그래도 실패하면 *"프로필을 불러오지 못했어요"* + 재시도 버튼 |
| E2 | 닉네임 미입력 / 공백만 | 저장 비활성화 + 인라인 에러 *"닉네임을 입력해 주세요"* |
| E3 | 닉네임 20자 초과 | 입력 길이 제한 + 카운터 |
| E4 | 아바타 형식/용량 위반 | SPEC-06 E1·E2와 동일 처리 |
| E5 | 아바타 업로드 실패 | 기존 아바타 유지 + 토스트 *"사진 업로드에 실패했어요"* |
| E6 | 통계 집계 쿼리 실패 | 통계 영역만 `-`로 표시하고 나머지 화면은 정상 노출 |
| E7 | 로그아웃 요청 실패 | 로컬 세션을 강제 정리한 뒤 `/login`으로 이동 (사용자가 로그인 상태에 갇히지 않도록) |
| E8 | 저장 버튼 연타 | 요청 중 `disabled` |
| E9 | 세션 만료 상태에서 진입 | 미들웨어가 `/login`으로 리다이렉트 |

- [ ] 아바타를 업로드하면 `/profile`과 AppBar에 즉시 반영되고 새로고침 후에도 유지된다.
- [ ] 루틴·완료·기록 통계가 실제 데이터와 일치한다.
- [ ] 로그아웃하면 `/login`으로 이동하고 보호 라우트에 재진입할 수 없다.
- [ ] 모든 변경이 Supabase `profiles` 테이블에 반영된다.
